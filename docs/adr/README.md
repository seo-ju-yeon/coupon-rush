# Architecture Decision Records

이 디렉터리에는 Coupon Rush에서 기술과 설계를 선택한 이유를 기록합니다. 현재 구현을 설명하고, 선택의 근거가 된 테스트와 아직 확인하지 않은 범위를 함께 남깁니다.

## 공통 구조

각 ADR은 제목과 상태 아래에 다음 순서로 작성합니다.

1. 배경과 문제
2. 선택 기준과 검토한 대안
3. 결정과 이유
4. 적용 흐름
5. 검증 결과
6. 한계와 후속 과제
7. 관련 코드와 테스트

실제 구현 이력과 개념 설명을 구분합니다. 구현 전에 겪지 않은 문제를 과거 장애처럼 쓰지 않으며, 학습용 예시는 그렇게 표시합니다. 선택한 기술의 장점뿐 아니라 추가 비용과 다른 대안이 적합할 조건도 기록합니다.

## 검증 범위

구현이 존재하는 것과 테스트로 동작을 확인한 것을 구분합니다. 테스트 결과에는 실행 조건과 확인한 값을 적고, 단일 JVM 테스트를 다중 서버 검증이나 성능 비교로 확대하지 않습니다.

공통 실행 방법과 저장된 테스트 결과는 [테스트 실행 및 검증 기록](../testing.md)에 모았습니다. 각 ADR에는 해당 결정과 직접 관련된 테스트만 연결합니다.

## 상태

| 상태 | 의미 |
| --- | --- |
| 제안 | 검토 중이며 아직 적용하지 않았습니다. |
| 승인 | 현재 프로젝트에 적용하여 사용합니다. |
| 대체됨 | 이후 ADR의 결정으로 대체했습니다. |
