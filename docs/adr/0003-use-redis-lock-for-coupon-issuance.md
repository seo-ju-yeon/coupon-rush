# ADR-0003: 쿠폰 발급에 Redis 분산 락 적용

## 상태

Accepted

## 결정일

2026-09-09

## 배경

한정된 수량의 쿠폰에 여러 요청이 동시에 접근하면 각 요청이 같은 발급 수량을 조회한 뒤 수정할 수 있습니다. 동시성 제어가 없다면 쿠폰이 준비된 수량보다 많이 발급되거나 저장 결과와 발급 내역 수가 달라질 수 있습니다.

프로젝트에서는 낙관적 락과 비관적 락을 먼저 구현하고 테스트했습니다. 최종 발급 API에는 여러 애플리케이션 인스턴스가 동일한 락을 공유할 수 있는 방식이 필요했습니다.

## 검토한 선택지

### `synchronized`

한 JVM 안에서는 요청을 순차 처리할 수 있지만, 서버가 여러 대이면 각 서버가 서로 다른 메모리 락을 사용합니다.

### JPA 낙관적 락

`@Version`으로 저장 시점의 충돌을 감지합니다. DB 행을 미리 잠그지 않지만 충돌한 요청은 실패하며, 정확한 수량만큼 발급하려면 재시도 정책이 추가로 필요합니다.

### DB 비관적 락

쿠폰 행을 조회할 때 쓰기 락을 획득합니다. 구현이 명확하지만 인기 쿠폰의 요청이 몰리면 DB 연결과 행 잠금 대기가 증가할 수 있습니다.

### Redis 분산 락

모든 애플리케이션 인스턴스가 Redis에 저장된 같은 락을 사용합니다. Redis 운영과 장애 대응이 추가로 필요합니다.

## 결정

- Redisson의 `RLock`으로 쿠폰 ID별 분산 락을 적용함
- 락 키는 `coupon:issue:{couponId}` 형식을 사용함
- 락 획득을 최대 10초 기다리고 실패하면 서비스 이용 불가 응답을 반환함
- lease time을 직접 지정하지 않고 Redisson Watchdog이 실행 중인 락의 만료시간을 갱신하도록 함
- 락 획득 후 별도 Spring Bean인 `CouponIssueService`를 호출하여 트랜잭션을 시작함
- 서비스 처리가 종료된 뒤 현재 스레드가 소유한 락만 해제함

## 결정 이유

- 서버가 여러 대여도 같은 쿠폰 ID의 요청이 하나의 락을 공유함
- 락의 범위를 전체 발급 기능이 아니라 쿠폰 ID 단위로 제한할 수 있음
- Redisson이 락 획득 대기, 소유권 확인과 Watchdog을 제공함
- 기존 Service의 비즈니스 로직을 변경하지 않고 Facade에서 락 책임을 분리할 수 있음

## 영향

### 장점

- 같은 쿠폰의 발급 요청을 순차 처리하여 정확히 재고 수량만큼 성공시킬 수 있음
- 서로 다른 쿠폰의 요청은 다른 락 키를 사용하므로 동시에 처리할 수 있음
- 애플리케이션 인스턴스가 여러 대인 환경에서도 사용할 수 있음

### 단점

- Redis 장애가 쿠폰 발급 API의 가용성에 영향을 줌
- 인기 쿠폰은 하나의 락에 요청이 집중되어 응답 지연이 발생할 수 있음
- 락 대기시간, Redis 연결 장애와 재시도 정책을 운영 환경에 맞게 조정해야 함
- 아직 실제 부하 환경에서 방식별 성능을 측정하지 않음

## 데이터 정합성 방어선

분산 락만 신뢰하지 않고 다음 DB 방어선을 함께 유지합니다.

- `coupons.version`의 JPA `@Version`
- `(coupon_id, user_id)` 유일 제약조건을 통한 중복 발급 방지
- `issued_quantity <= total_quantity` 체크 제약조건
- 하나의 발급 쿠폰을 한 주문에서만 사용하도록 하는 유일 제약조건

## 검증

`CouponRedisLockConcurrencyTest`에서 Testcontainers로 PostgreSQL과 Redis를 실행하고 다음 조건을 검증합니다.

- 서로 다른 사용자 20명이 같은 쿠폰을 동시에 요청함
- 쿠폰의 전체 수량은 5개임
- 성공 5건, 품절 15건이 발생함
- 락 타임아웃과 낙관적 락 충돌은 발생하지 않음
- 쿠폰의 발급 수량과 실제 발급 내역이 모두 5건임

## 후속 과제

- k6를 이용해 낙관적 락, 비관적 락과 Redis 분산 락의 처리량 및 응답 시간을 비교함
- Redis 장애와 락 타임아웃을 관찰할 메트릭과 로그를 정의함
- 부하 테스트 결과에 따라 락 대기시간과 재시도 정책을 조정함
